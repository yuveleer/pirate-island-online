# Пиратский остров — онлайн 12×12, версия 2.0

Это серверный комплект последней версии, а не уже опубликованный сайт. Интерфейс, иллюстрации и анимация находятся в public/index.html; серверная логика — в game.js.

## Обновление существующего сервиса Render
1. Распакуйте архив. Откройте папку проекта.
2. В репозитории GitHub ЗАМЕНИТЕ файлы package.json, server.js, game.js, render.yaml и public/index.html. Сохраните пути: index.html обязан лежать в public, а не в корне.
3. Загрузите также папку test и эту инструкцию. Не загружайте ZIP вместо распакованных файлов. package.json, server.js и game.js должны лежать в корне репозитория, без дополнительной папки над ними.
4. Commit changes. Если включено автоматическое развёртывание, Render начнёт его. Иначе откройте существующий сервис → Manual Deploy → Deploy latest commit.
5. Настройки: Web Service; Node; Root Directory — пусто; Build Command: npm install; Start Command: npm start; Health Check Path: /health.
6. После успешного запуска откройте адрес сервиса с /health: он должен вернуть ok. Затем откройте корень сайта. В заголовке должно быть 12×12 / Онлайн / Пещеры и лёд ×2.
7. Создайте НОВУЮ комнату, отправьте другу приглашение. Друг нажимает «Присоединиться». Старые комнаты и сохранения не переносятся.

Пример структуры репозитория:

package.json
server.js
game.js
render.yaml
public/
  index.html
test/
  game.test.js
README-RU.md

Создавать ещё один сервис не требуется, если ваш текущий сервис — Node Web Service. Не выбирайте Static Site: игра требует работающего сервера.

## Первый запуск на Render
Создайте репозиторий, загрузите файлы с указанной структурой. New → Web Service → подключите репозиторий. Используйте команды выше. Альтернатива: New → Blueprint использует render.yaml. Проверьте тариф и стоимость перед подтверждением. Конфигурация содержит plan: free, но наличие и ограничения плана проверяйте в интерфейсе платформы.
Документация: https://render.com/docs/deploys

## Проверка на компьютере
Нужен Node.js 20 или новее. В папке проекта:

npm test
npm start

Откройте http://localhost:3000. Создайте комнату. Для второго игрока используйте другой браузер или приватное окно, иначе вкладки разделят один ключ игрока. localhost работает только на этом компьютере — для друга через интернет нужен публичный адрес.

## Возможности
- Поле 12×12, 100 клеток суши, 24 монеты.
- Четыре пещеры, шесть скольжений ×2, пушка до края острова, лошади, ром, капитаны, лабиринты.
- Рисованные объекты и яркие эффекты прямо на поле. Никаких полноэкранных заставок.
- Онлайн-комнаты на двух игроков, управление только своей командой.
- Серверная проверка правил, очереди и ревизии; скрытые клетки не раскрываются клиенту.
- Обновления через SSE, команды через HTTP POST. Автоматическое переподключение.
- Восстановление места по ключу, сохранённому в том же браузере.
- Поддержка safe-area, мобильной вёрстки, переключения анимации и системного уменьшения движения.

## Ограничения
Комнаты находятся в оперативной памяти ОДНОГО процесса. Перезапуск, сон, обновление сервиса или авария уничтожают партии. Переподключение восстанавливает только ещё существующую комнату. Для постоянного сохранения нужна база данных. Запускайте один экземпляр сервера, не несколько реплик.

Неактивные комнаты без соединений удаляются через 24 часа. Лимит — 250 комнат. Простое ограничение создания комнат не заменяет DDoS-защиту. Это прототип для частных партий, не публичный сервис с аккаунтами и античитом.

Приглашение не содержит ключ игрока, но позволяет занять второе место. Отправляйте его только другу. Для возврата нужен тот же браузер и сохранённый localStorage; при очистке данных восстановление места не предусмотрено.

Ключ соединения SSE находится в query string. Не публикуйте серверные/прокси-логи. Для массового публичного продукта нужна защищённая сессия и дополнительная инфраструктура.

Входя из фонового режима телефона, дождитесь восстановления соединения. Пропущенные ходы синхронизируются по состоянию; если пропущено несколько, длинная анимация не проигрывается повторно. Иллюстрации оригинальные, сторонние игровые ресурсы не используются.

Синтаксис, серверные тесты, HTTP и SSE проверялись локально при сборке. Публичное размещение и настоящие телефоны здесь не проверялись.
